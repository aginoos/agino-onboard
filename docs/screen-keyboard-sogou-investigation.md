# 搜狗 NG 接入与验证

2026-10-04。基线 agino-keyboard 0.1.8（f96727c），目标测试版本 0.1.9。实际使用本机已安装的搜狗 NG 10.0.10.0-1403 的程序文件，在自有 Docker SDK、私有 DBus、Xvfb / 嵌套 KWin、隔离 CPIS 用户数据中验证。没有切换、重启本机输入法或读取用户正在输入的内容。

## 根因与调查更正

搜狗 NG 的最终候选经 CPIS keyflow 处理，不写入标准 Fcitx `InputPanel::candidateList()`；原桥接只读取标准接口，所以候选栏为空。原始 `com.cpis.engine` 的候选索引与最终面板候选不同，不能直接调用它的 `SelectCandidate` 提交。

先前只读调查使用裸输入法 id 查询 `config_preedit_type` 得到 0，但该 id 不是用户的 CPIS 上下文 uid。这个结果不能证明本机用户关闭了预编辑，先前的配置判断应撤回。实际私有运行时确认的 uid 格式是 `登录用户名#im.module=fcitx5|im.name=com.sogou.ime.ng.fcitx5.deepin`，由进程真实 uid 的 passwd 记录生成，不使用 USER 环境变量推测。本次没有更改用户的预编辑选项。

## 实现

仅当键盘拥有显示租约、当前上下文可编辑且非敏感、当前输入法确为搜狗 NG 时启用适配。使用 Fcitx 自带的异步 DBus API，无新增 Qt 或搜狗库链接依赖。

读取 CPIS 的最终 `result_composition`、`result_candidate_result` 和前后页状态。组合串经正常 clientPreedit 通道交给支持预编辑的目标应用；选择候选先设置 keyflow 的最终候选焦点，再发送普通虚拟空格事件，由搜狗完成整词或分段选择；翻页发送普通 PageUp / PageDown 事件。不先提交字母、再用退格重写目标内容。

接管窗口为 `composition`，不是此前猜测的 `pc_composition`。只隐藏这个逻辑窗口，不隐藏 status 或 softkeyboard。收起、键盘 DBus 连接异常断开、适配错误及正常后端退出时恢复已接管的 composition；切换焦点或进入敏感输入时清理本适配的预编辑。

所有查询都绑定上下文代次和候选修订版本。输入事件或 CPIS 更新使旧候选不可选择，延迟回复不能提交旧索引；单项查询错误先恢复原面板（包括缓存尚为空、刚开始输入时的查询失败），成功但不一致的批次最多重试三次，避免无限查询。监听服务更换并按需重新取数，没有常驻轮询。

## 验证边界

回归记录位于 `out/components/agino-keyboard-validation/sogou-019/`。原版候选为空、旧实现隐藏窗口名错误，以及待更新候选仍可提交，都已先复现为失败测试。新增 DBus 协议夹具覆盖延迟响应、过期索引、部分查询失败、有界重试、恢复与析构恢复命令。

最终 31 项 CTest 全部通过（254.55 秒），仓库 16 项 unittest 通过。新增搜狗测试分别在 X11、原生 Wayland、text-input-v3 和 XWayland 下运行；原生独立面板信号断言仅适用于 X11，其他路径明确跳过该可见性测试，不计为完成实机验收。实际 Qt 和 GTK 目标都验证了预编辑与提交。

实际搜狗测试覆盖候选序列与 CPIS 一致、光标处预编辑、整词/分段选词、分页、旧版本请求拒绝、收起/重新显示、切换输入法、敏感输入清理、不同目标输入和显示租约连接断开。测试保留搜狗本身的焦点离开处理；目标应用如何处理预编辑取决于其输入法实现。

CPIS 的 Show 方法不发出 keyflow 的 ShowWindow 信号，因此不能用这个信号声称直接 Show 的可视化验收。原生 X11 测试验证独立面板隐藏信号、恢复后继续输入能重新显示候选；协议夹具验证恢复命令。嵌套 Wayland / XWayland 会话中的 CPIS 原生窗口为虚拟窗口，独立窗口像素可见性需要完整 DDE 实机验收。本次不认证旧 Fcitx4 搜狗、其他搜狗版本、完整 DDE Wayland 会话或触屏硬件。

## 交付

安装新版后注销并重新登录，确保 Fcitx 加载新桥接模块。无需安装搜狗开发包；本包不包含搜狗程序文件，搜狗兼容仅在用户已安装匹配版本时启用。

测试包 441,640 字节，安装载荷约 2,172 KiB。依赖与 0.1.8 完全相同，并与本次 ELF 重新计算的依赖匹配；6 个 ELF 文件均未链接 LayerShellQt。安装模拟为仅升级 agino-keyboard、零个新增包。本次 GUI 二进制与 0.1.8 相同；实际载荷变更为桥接模块、模块版本配置和 README。
