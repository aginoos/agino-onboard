# Qt键盘内存优化：轻量常驻与按需界面

用户目标：维持Qt/DTK功能和界面，将收起后USS/PSS降低到Slint级别（此前实测USS10908KiB、PSS11399KiB），RSS也争取接近25580KiB。不采用Swap、清空系统缓存或只统计一个子进程的方法。

## 实测与决策

当前安装的Qt0.1.16 PID124104收起并卸载界面时RSS97388KiB、USS28460KiB、PSS36681KiB、Swap0。随后映射分解：堆10352KiB、匿名4968KiB；QML/Quick/DTKDeclarative与图像库仍常驻。现有malloc_trim/QFont清理已执行，不能解除进程对Qt图形运行时的生命周期。

私有SDK/Xvfb探针：仅QtCore进程RSS9708KiB、PSS7352KiB、USS6280KiB；QApplication+托盘+快捷键探针RSS40208KiB、PSS25646KiB、USS14164KiB。后者即使不创建QML仍高于目标。因此选择QtCore/DBus/X11/Wayland轻量控制器，保持原Qt/DTK窗口进程和控件，收起3秒后退出窗口进程。短时收起继续复用。托盘、快捷键、输入来源/锁屏、公开DBus入口由控制器保留。

不是把Qt界面改成Slint。显示时必须汇总控制器与界面两进程，隐藏后必须无GUI子进程和QtGui/Widgets/QML/Quick/DTK映射；同时报告SwapPss。

## 边界设计

- /usr/bin/agino-keyboard：QtCore控制器，保持org.agino.KeyboardUi1 /Keyboard公开接口；DBus异步转发，禁止同步互等死锁。
- /usr/libexec/agino-keyboard-ui：现有Qt/DTK界面与输入桥客户端；内部org.agino.KeyboardPanel1，绘制/预编辑/候选/设置/多触点代码保持。
- 控制器拥有Fcitx VirtualKeyboard接口、托盘与全局快捷键。界面只在被呼出时启动；窗口按键仍由其Fcitx客户端按权威epoch发送。
- 退出前协商交接；有未完成显示/设置请求则不退出；正在退出期间的新请求缓存到重建后。无任何输入文本写入交接状态；仅保存几何、输出、caps及帧计数。
- 锁屏/安全策略、首选输入法仅初次启动或偏好修改时应用，重建不重设用户选中的输入法。按键/候选仍拒绝过期上下文。
- 原有自动触屏/笔呼出、物理键不误隐藏、关闭模式、托盘菜单、设置、快捷键和应用入口保持。缺少Wayland协议时由窗口进程实际确认并提示。
- 子进程崩溃释放显示租约/按键；控制器仍可重新呼出。控制器退出必须同时停止窗口进程。

## 0.1.18：显示态优化与 Slint 对照研究

用户进一步要求优先参考 Slint 曾经的内存优化。已读取“用 Slint 实现屏幕键盘应用”会话相应两轮诊断、完整报告 `docs/keyboard-slint/memory-optimization-0.1.2.md` 和提交 `5560b88feddac0be2295035a6627f38bfa958f35`，并核对当前0.2.3仍保留的源码：`platform/x11.rs`、`platform/wayland.rs`、`platform/pixels.rs`。Slint源码只读，没有改动该工作树。

Slint当时的关键收益不是降低颜色/分辨率或裁剪功能，而是：X11采用render_by_line和约64KiB带状输出；Wayland直接绘制进wl_shm且包括旧尺寸占用在内最多两张缓冲；移除常驻RGB与整图BGRA转换副本；截图临时图仅在截图时生成；窗口销毁后归还空闲堆页。其200%设置阶段PSS39.83→20.60MiB，不能将旧版不同阶段数字与本轮Qt直接作同条件因果比较。

本轮分步ABBA试验（对照/修改/修改/对照），100%宿主私有会话、真实拼音候选，汇总所有应用PID，单位KiB：

|---|---:|---:|---:|---:|---|
|显式PNG解码provider|50733|45966|45389|50698|保留；修改组不再映射AVIF/HEIF/JXL/RAW/x265/rsvg|

各行比较各自的对照二进制，不能把不同会话的差值机械相加；最终同会话对照另列。探测输出有部分共享swap记录，但SwapPss与进程VmSwap为0；未主动换出内存。最终无探针测量单独检查swap。

为核对Slint的分配器原因，复用其malloc-probe.c思路、按PID写独立报告，并额外采集大于512KiB分配的原生调用栈。该诊断只用于归因，不作为最终资源数字。200%候选显示时界面arena约17MiB、活跃分配约14MiB、空闲约3MiB；X11共享图像memfd:xorg PSS约2.45MiB（总位图约4.9MiB，另与Xserver共享），不能把所有匿名页或整个arena都冒称可释放帧副本。观测到的两次约1.04MiB malloc来自QRasterPaintEngine填充路径；未据此声称Qt存在Slint旧版的多份常驻全帧RGB/BGRA副本。

另一次独立探针，展开候选再收拢后，malloc_trim将合计PSS56589→54657KiB，约回收1.89MiB；设置关闭后再trim为55657→55577KiB，仅80KiB。此试验没有清理字体和JS堆，没有加入产品的定时trim循环。Qt仍有大量活跃界面对象与QML/DTK运行时开销，不能把Slint的“空闲堆约21MiB”诊断直接套用于当前Qt。若继续争取接近Slint，需对活跃控件/文字缓存和绘制路径做更深的原型对照，再决定是否改为QtGui/QPainter直接渲染；不得先宣称框架决定了不可优化，也不得只更换渲染器名称冒充完成。
