# 0.1.20：恢复正常字体缓存复用

用户明确选择：显示期间停顿后仅节省约0.4–3.1MiB PSS，不值得增加重建工作；撤销此项主动回收。此偏好优先于此前追求Slint USS/PSS数值的目标，不再次以空闲清缓存方式追数值。

## 修改范围

移除NativePanel每帧启动的1秒cacheTrimTimer，以及其文字布局清空、QFont::cleanup和malloc_trim调用。保留估算成本128KiB/最多128项的文字布局缓存，字体变化时失效、面板销毁时正常释放。收起后的界面进程销毁与常驻控制器保留，未替换本机运行应用。已有多语言候选/设置/长按在停顿前后的实际事件用例改名为正常空闲场景，继续验证像素与输入稳定性。

0.1.19及其安装包/原始JSON保留为历史证据；不把其空闲回收后的数字当作0.1.20结果。Qt自身正常字体缓存管理仍然生效。

## RSS排查依据

使用investigate流程先核对源码调用路径、现有smaps和ELF依赖，再以同一私有Wayland会话对照新的完整应用。当前Slint0.2.3直接NEEDED仅xkbcommon/fontconfig/libgcc/libm/libc/loader；Qt原生界面仍需要QtGui/Core/DBus、DTK和X11/Wayland库。DTK系统平台主题libqdeepin.so还依赖QtWidgets，故不能因界面不再使用QWidget按钮就声称完全不加载QtWidgets。前端未加载QtQuick/QML，不能把差距归因于仍在使用QML。

Qt控制器与界面分成两个进程，RSS求和会重复计算共同映射的库页；Slint当前为单进程。共享库映射的页与其他DDE应用共享，RSS每个进程全额计入，PSS按共享者分摊。需要同时看绝对驻留页和独占内存，不能把RSS直接当作系统增量。Slint原生可执行文件包含已编译UI/渲染代码，分类时必须把其主程序映射一并纳入比较，不能只比较.so文件大小。

此前1×只读smaps中，Qt界面共享库映射RSS36,732KiB/PSS5,986KiB，控制器共享库RSS13,324KiB/PSS1,567KiB；这支持共享库驻留和多进程累计是主要RSS来源，但不是新0.1.20的精确数值。新2×对照将另列buffer、字体/文件、匿名堆及程序/库映射。

## RSS 差距的同场景拆分

取两组首次活动设置样本（各版2个样本），逐映射分类后计算中位数。Slint静态编入的运行代码计入主程序，避免只比较.so而漏算Slint成本。数值不是磁盘库大小或虚拟地址空间，而是smaps实际驻留页；RSS仍按每个应用进程求和。

| 分类 | Qt RSS / PSS MiB | Slint RSS / PSS MiB |
| --- | --- | --- |
| 主程序和运行库 | 49.45 / 8.45 | 15.29 / 12.00 |
| 其他文件（含字体映射） | 7.61 / 2.28 | 6.91 / 2.19 |
| 窗口和光标共享缓冲 | 9.82 / 4.91 | 9.81 / 4.91 |
| 堆、匿名页及其他 | 5.96 / 5.95 | 3.13 / 3.12 |

Slint当前原生二进制运行依赖更少；Qt/DTK是较通用的运行时，系统主题还引入Widgets、DTKCore、Network、ICU、字体整形等驻留页。Qt分离控制器和界面，RSS重复累计双方共同映射的页；Slint当前为单进程。Qt程序/库RSS49.45MiB而PSS8.45MiB，Slint对应15.29/12.00MiB，说明Qt的RSS差距主要不等于新增独占内存。Qt自身堆/匿名页也略多，不能把所有差额笼统归为共享。两者窗口缓冲几乎相同，字体/文件映射也接近；恢复正常字体缓存不会消除这些运行时结构差异。
