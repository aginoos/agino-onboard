# 屏幕键盘显示状态修复（0.1.3）

用户在 Deepin 搜狗环境通过 Ctrl+Alt+K 呼出键盘后，松开快捷键就收起；已显示时按其他实体按键也会收起。用户明确要求实体按键不能收起已显示的面板。

## 根因与行为

本机直接调用 `/Keyboard.Show` 后保持显示，通过真实 KGlobalAccel 快捷键则在 K 释放时隐藏。焦点桥的 `PhysicalKey` 通知覆盖非虚拟按键的按下和释放；旧界面把该通知和桌面设备来源都送入状态机。自动模式收到实体键盘来源后清除手动显示标记并隐藏，随后输入法状态更新也会根据来源再次隐藏。

界面取消输入法 `PhysicalKey` 对显示状态的控制，桌面设备接口继续跟踪来源。实体按键按下、释放都不再隐藏面板，也不自动打开隐藏面板。已显示状态独立于可编辑状态保留，避免 Tab/Shift+Tab 切换控件时短暂的 FocusOut 把键盘收起。失去目标时仍取消全部触点、释放按住的键，并禁止继续输入。

主动关闭、关闭模式、锁定、后端断连和布局尺寸不足仍会收起。关闭同时清除旧触屏来源，防止焦点通知先于实体来源到达时，旧 Touch 状态重新打开面板。新的触屏或笔操作仍可按自动模式打开。

方案五 QML、输入桥接协议、自有 Wayland 插件和收起后的资源回收保持原实现。本轮没有重新测量内存或首帧延迟。

## 回归与本机验证

证据目录：`out/components/agino-keyboard-validation/show-visibility/`。

- 快捷键回归先失败再通过：真实 KGlobalAccel 触发，XTEST 发送快捷键按下/释放，确认收到桥接释放通知后面板继续显示，3.5 秒后仍未卸载。XTEST 被桌面来源检测过滤，因此此测试只证明快捷键释放路径，实体来源另测。
- 状态机回归分别验证实体来源、临时失焦和关闭后的延迟来源。RED 日志保留；最终 14 个 QtTest 用例通过。覆盖来源在 FocusOut 前、两次焦点通知之间、FocusIn 后到达；失焦释放 Ctrl 并拒绝字符；关闭后不重开；新 Pen 可打开；Off 和尺寸不足可关闭。
- 最终完整 SDK 回归：20/20 CTest，0 失败，200.71 秒，包括 X11、原生 Wayland、文本输入 v3、XWayland、后端恢复、窗口及协议生命周期、深浅色 QML 和快捷键。日志为 `ctest-final.log`。
- 最终 deb 安装至独立完整 DDE X11 虚拟机：通过 QEMU `input-send-event` 的硬件键盘事件验证冷呼出、热呼出、持续收起卸载后呼出及 700ms 长按快捷键四种情况。松开后面板保持；实体 `a` 到达自有密码输入框，面板保持；Tab、Shift+Tab、四个方向、Ctrl、Alt、Shift、Esc 和 F2 均保持面板显示。输入前后的活动应用仍为测试目标。记录只保留输入结果布尔值，不记录用户输入。
- 最终包的完整 DDE X11 输入套件：14 通过、0 失败、11 项按私有会话/其他环境条件跳过。仓库 unittest：16/16 通过。
- 本机替换的仅为已确认的 Agino 界面进程；Fcitx、搜狗与其虚拟键盘接口仍为原连接，虚拟键盘配置存在状态不变，未重启或重载输入法。界面使用原偏好及环境。

QEMU 硬件事件补充实体来源验证，不能代替真实触屏、笔或完整 DDE Wayland 设备验收。焦点顺序边界由状态回归覆盖；GTK 硬件夹具只有一个密码输入框，不宣称已在真实多输入框应用中完成全部切换测试。
