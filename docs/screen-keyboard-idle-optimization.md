# 屏幕键盘持续收起后的内存优化（2026-10-03）

优先目标是持续收起后再降低约 40%；输入状态以 PSS 单项实验，保留方案五外观和输入行为。逐项对照与最终安装包验证分别记录，不能把 RSS 降幅与 PSS 混用。

## 测量方法

自有 Deepin 25 完整 DDE X11 KVM 虚拟机，4 GiB、2 vCPU、1920×1080。每项主要对照启动 3 个全新 GUI 进程。读取 `/proc/PID/smaps_rollup` 和 `smaps` 元数据，USS 为 Private_Clean + Private_Dirty；数字不包含已有 Fcitx 或桌面进程。单位为 MiB。拼音输入固定夹具产生 128 个候选词，输入与候选内容不记入日志。隐藏后等待 5 秒采样。

基线使用前一轮优化的应用源码 5d3b820，保留同次虚拟机环境的新基线 baseline.json。与上一报告的不同采样不能视为精确配对。

## 实现与延迟

短暂收放保留缓存；隐藏满 1 秒请求释放渲染资源，满 3 秒才销毁窗口和 QML。保持 KeyboardState、FcitxClient、会话服务和输入法进程，销毁前清除停靠区域及屏幕连接，取消按住的触点。Caps 状态仍由同一 KeyboardState 持有，候选由仍在运行的输入法重新绑定；旧按键不会重放。

GUI 线程在完整销毁 QQuickView 后调用 QFont::cleanup，然后由 glibc malloc_trim 归还空闲页。前者虽在公开头文件声明，Qt 源码将其标为内部钩子；本实现审阅和验证于 Qt 6.8.0，升级 Qt 必须重新审阅与测试。Qt 使用线程局部字体缓存和引用计数，存活的字体数据根据缓存代次重新加载。[Qt 6.8.0 字体缓存实现](https://raw.githubusercontent.com/qt/qtbase/v6.8.0/src/gui/text/qfont.cpp)

Status 增加 showSerial、firstFrameSerial 和 firstFrameMs：从本地 Show 进入，到该显示请求对应的 Qt afterFrameEnd。记录不可变计时样本、在帧开始绑定请求、跨渲染线程原子读取，避免旧帧计入新请求。自动呼出也记录；显示期间再次 Show 保留手动显示语义，不重置计时。它测的是 Qt 首帧提交，不代表合成器上屏或实际屏幕发光。[Qt QQuickWindow afterFrameEnd](https://doc.qt.io/qt-6.8/qquickwindow.html#afterFrameEnd)

字体实验中的持续收起重建首帧 12 次：130.5–244.4 ms，中位数 171.3 ms；同时 DBus 返回中位数 107.0 ms。短暂收起保留缓存。反复卸载/重建后 PSS 约 24.0–24.4 MiB，严格 40% 并非每一次都达到；必须报告稳定范围，不能仅选最好的一次。
